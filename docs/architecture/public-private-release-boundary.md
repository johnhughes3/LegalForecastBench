# Public/private release boundary

Status: accepted for the additive corpus split.

The public repository owns exactly two cross-repository release contracts: `legalforecast.forecast-release.v1` contains outcome-blinded execution inputs, and `legalforecast.labels-release.v1` contains outcomes and scoring policy. The forecast release commits release and policy identity, code and packet-builder versions, canonical case and prediction-unit indexes, exact model-visible document indexes, and the bytes of every document, packet, and prompt. The labels release binds the forecast digest and the exact scoreable unit set without giving forecast execution an API for label bytes or paths; unscoreable model-visible units have no fabricated labels.

The public package owns canonical issuance and validation. A private corpus producer supplies strict uncommitted drafts and referenced public artifact bytes to `legalforecast release issue`; it does not copy a schema or serialize release bytes itself. `legalforecast release issue-synthetic` proves the complete producer-to-validator flow without providers or private data.

Public execution begins only from `forecast-release.json`. `legalforecast run execute` binds the release digest, exact model-registry bytes and officially eligible pinned entry, harness, authenticated prompt treatment (currently `none`), repeats, account, owner-approved ceiling, and plain approval reference into one local SQLite run identity. The release runner currently fixes the harness to the native execution path; any non-native harness requires its own authenticated adapter path rather than relabeling native calls. Because `forecast-release.v1` authenticates exact prompt bytes rather than an ablation recipe, a non-default ablation requires a separately issued release and cannot be supplied as a free-form receipt label. Each unit/repeat cell is reserved transactionally before the existing provider spend authority can authorize transport; an interrupted or unknown-usage call remains reserved and cannot be called again. One explicitly retryable, definitively nonbillable HTTP 429 may authorize a single transaction-coupled replacement request, while ambiguous, nonretryable, and reconciled attempts never do. Completed cells resume only after their create-only `legalforecast.public-run-receipt.v1` bytes match the ledger commitment. Receipts contain prompt and final request-body hashes, the authenticated public model-registry version, validated usage, estimated registry-price cost, and normalized public predictions, but never provider account identifiers, label paths or bytes, source text, raw model output, or raw provider responses. `legalforecast run issue-fixture` plus `run execute --dry-run` exercises the same ledger and receipt path with a deterministic three-case no-network transport.

Acquisition state, PACER records, task leases, Beads comments, owner prose, historical roots, approval artifacts, decision text, and other intermediate lineage are intentionally absent. Relative paths are containment-checked, artifacts are read without following links, outcome-bearing document roles are unrepresentable, and the two releases use the existing artifact canonical JSON and commitment profiles. Generic issuance reverifies every referenced byte immediately before create-only publication, and execution rereads and reverifies the selected packet, prompt, or document immediately before use. This boundary is additive through the completed Cycle 1 tag and does not change any current official-run input, codec, validator, or execution semantic.
