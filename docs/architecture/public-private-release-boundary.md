# Public/private release boundary

Status: accepted for the additive corpus split.

The public repository owns exactly two cross-repository release contracts: `legalforecast.forecast-release.v1` contains outcome-blinded execution inputs, and `legalforecast.labels-release.v1` contains outcomes and scoring policy. The forecast release commits release and policy identity, code and packet-builder versions, canonical case and prediction-unit indexes, exact model-visible document indexes, and the bytes of every document, packet, and prompt. The labels release binds the forecast digest and the exact scoreable unit set without giving forecast execution an API for label bytes or paths; unscoreable model-visible units have no fabricated labels.

The public package owns canonical issuance and validation. A private corpus producer supplies strict uncommitted drafts and referenced public artifact bytes to `legalforecast release issue`; it does not copy a schema or serialize release bytes itself. `legalforecast release issue-synthetic` proves the complete producer-to-validator flow without providers or private data.

Public execution begins only from `forecast-release.json`. `forecast-release.v1` remains a generic byte-authentication contract: its ordinary validator does not define packet-internal fields. The narrower public-runner executable profile additionally requires every authenticated packet to be a JSON object whose top-level `case_id` matches the release unit and whose canonical ISO `decision_date` agrees across the case and is on or after the selected model's UTC release anchor. The provider-free `legalforecast release issue-synthetic` producer emits this profile. The generic `legalforecast release issue` command also issues it when its forecast draft names date-bearing packet artifacts; a production corpus builder remains responsible for deriving those packet dates from its authenticated case state before calling the public issuer. This runner-only restriction does not change which generic v1 releases validate; a v1 release whose packet producer does not supply the executable fields is valid but intentionally not runnable here.

`legalforecast run execute` binds the release digest, exact model-registry bytes and officially eligible pinned entry, harness, authenticated prompt treatment (currently `none`), repeats, account, owner-approved ceiling, and plain approval reference into one local SQLite run identity. The release runner currently fixes the harness to the native execution path; any non-native harness requires its own authenticated adapter path rather than relabeling native calls. Because `forecast-release.v1` authenticates exact prompt bytes rather than an ablation recipe, a non-default ablation requires a separately issued release and cannot be supplied as a free-form receipt label. Every case/repeat call groups the complete sorted unit set for that case behind one authenticated prompt and reserves one ledger cell before the existing provider spend authority can authorize transport; an interrupted or unknown-usage call remains reserved and cannot be called again. A complete provider response is committed with its digest to the local ledger before spend settlement so a process death can replay the exact bytes without another provider call; ordinary validation or publication rejection clears that replay material and remains terminal. One explicitly retryable, definitively nonbillable HTTP 429 may authorize a single transaction-coupled replacement request, while ambiguous, nonretryable, and reconciled attempts never do. Completed case calls resume only after their create-only `legalforecast.public-run-receipt.v1` bytes match the ledger commitment, including the full required unit set; legacy singleton receipts remain readable. Receipts contain prompt and final request-body hashes, the authenticated public model-registry version, validated usage, estimated registry-price cost, and normalized public predictions for every required unit, but never provider account identifiers, label paths or bytes, source text, raw model output, or raw provider responses. `legalforecast run issue-fixture` plus `run execute --dry-run` exercises the same ledger and receipt path with a deterministic three-case no-network transport.

Acquisition state, PACER records, task leases, Beads comments, owner prose, historical roots, approval artifacts, decision text, and other intermediate lineage are intentionally absent. Relative paths are containment-checked, artifacts are read without following links, outcome-bearing document roles are unrepresentable, and the two releases use the existing artifact canonical JSON and commitment profiles. Generic issuance reverifies every referenced byte immediately before create-only publication, and execution rereads and reverifies the selected packet, prompt, or document immediately before use. This boundary is additive through the completed Cycle 1 tag and does not change any current official-run input, codec, validator, or execution semantic.
