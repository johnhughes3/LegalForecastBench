# Published snapshot store recovery

`legalforecast acquisition recover-published-snapshot-from-store-commitment` is the provider-free, create-only recovery issuer for a complete saturated `legalforecast-cycle-acquisition-v1` snapshot whose registered directory is no longer available but whose exact commitments and append-only source rows remain authenticated by the cycle store.

The command requires an externally pinned SHA-256 for the unique regular SQLite store, the exact committed snapshot ID, the SHA-256 of the stored canonical `manifest_json` bytes plus the publisher-mandated trailing LF, and a new output directory under an already-existing non-symlink parent. It opens the database and lock through bound no-follow descriptors, holds the store lock, proves the stored cycle policy hash, cycle and batch identity, complete/saturated publication state, canonical manifest text, registry timestamp, and historical registered path, and never opens the store writable.

Recovery uses the existing `CycleAcquisitionStore` snapshot projector. Every payload other than `observations.jsonl` must reproduce its stored byte count, row count, and SHA-256 in full. `observations.jsonl` may use only the first stored `row_count` rows of the current append-only projection, and that exact prefix must match the stored byte count and SHA-256. The issuer neither selects rows by timestamp nor generates a new timestamp. It stages all six payloads plus the exact manifest, runs `verify_snapshot`, rechecks unique regular bytes, rechecks the source store digest, and atomically renames without replacement.

The recovery output is the existing snapshot schema and does not introduce a new authenticated artifact schema. A successful JSON report identifies the output root, snapshot and batch IDs, cycle/store/manifest hashes, the recovered observation row count, and all six payload hashes.

For downstream export, `legalforecast acquisition prepare-disposable-snapshot-recovery-store` creates a new private directory containing a byte-derived `cycle-acquisition.sqlite3` and empty lock. It verifies the recovered snapshot against the same commitments, then changes only the copy's registered snapshot path through `CycleAcquisitionStore.rebind_recovered_published_snapshot_path`. The source store stays locked, read-only, and digest-identical. Operators pass the returned copy path—not the canonical store—to `export-cohort-observations`, then run `verify-cohort-observations` and enforce the expected complete snapshot coverage.

Neither command contacts a provider, reads credentials, purchases documents, mutates the canonical store, accepts an existing output, follows a symlink, admits a multiply linked store or payload file, or reconstructs JSON/timestamps from memory.
