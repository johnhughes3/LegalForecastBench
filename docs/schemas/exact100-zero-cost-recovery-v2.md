# Exact-100 zero-cost recovery v2

`legalforecast.exact100_zero_cost_recovery_request.v2`, `legalforecast.exact100_zero_cost_recovery_receipt.v2`, and `legalforecast.exact100_zero_cost_recovery_run.v2` supersede the v1 recovery evidence only for post-selection terminal exclusion.

The bounded producer accepts only a canonical `legalforecast.exact100_zero_cost_recovery_plan.v1` object containing exactly one allowlisted selected pair. It derives, rather than accepts at execution time, the candidate, source-document, docket, and docket-entry identifiers from the plan and authenticated selection. Its present fixed tuple is candidate and CourtListener docket `72449171`, RECAP document `480673755`, and docket entry `465468661`; the related complaint `471866646` is not a recovery target. The producer performs only the direct `GET /recap-documents/{id}/` needed for that pair. On a public metadata success, it makes one additional exact `GET /docket-entries/{id}/` and requires the returned entry ID and docket ID to match the fixed tuple and its `recap_documents` membership to contain `480673755` before downloading. A 404 terminal observation remains one document GET. It does not expose search, lists, pagination, recorded-response or document fixtures, Firecrawl, Case.dev, PACER, RECAP Fetch, brokers, or a fee-bearing route. Offline tests inject transports only through a private in-process seam that is absent from the command surface.

The v2 request binds the exact predecessor selection digest and names one selected target document. The verifier independently replays that selection and requires the candidate's `identity_resolution.courtlistener_docket_id` plus the selected document's `source_document_id`, `document_role`, and `courtlistener_docket_entry_id` to match the request. Caller-supplied identifiers do not establish terminal authority.

The v2 receipt removes the self-asserted CourtListener request count. Instead it commits a closed `legalforecast.exact100_zero_cost_recovery_rest_observation.v1` object, its canonical JSONL `legalforecast.exact100_zero_cost_recovery_rest_observation_transcript.v1` bytes, and the exact raw response sidecar `rest-observation-response.bin`. The observation commits the request, exact candidate/document/docket/entry tuple, exactly one transcript record, and a completed nonretryable unrecovered `unavailable` disposition. The sole transcript record must be the exact CourtListener RECAP-document `GET`, must terminate with status 404, and must commit the SHA-256 of the replayed raw response bytes. Empty or multirow transcripts and missing, synthesized, or changed response bytes fail closed. No transcript may assert a paid, PACER, or RECAP Fetch route.

The completed v2 run card binds exactly the request and selection inputs plus receipt, REST-observation, REST-transcript, and raw-response outputs. Its provider activity represents only the bounded noncharging CourtListener REST producer. The verifier accepts no v1 recovery artifact for terminal exclusion.

A direct 404 produces the above terminal surface. A successful, explicitly public and unrestricted response instead downloads only a CourtListener PDF whose initial and final URLs remain canonically bound to RECAP document `480673755`, then emits a separate `legalforecast.exact100_zero_cost_recovery_public_document.v1` manifest sidecar with the request commitment and the PDF's SHA-256 and byte count. That public recovery is not terminal-exclusion authority: it retains the candidate for ordinary authenticated handoff and never emits a terminal receipt, observation, or run card. Authentication failures, rate limits, 5xx responses, malformed metadata, identity drift, ambiguous availability, restrictions, redirects to another document, and unsafe URLs fail closed without either outcome.
