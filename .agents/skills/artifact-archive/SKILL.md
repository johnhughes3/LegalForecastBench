---
name: artifact-archive
description: Preserve surviving GitHub Actions artifact ZIPs in protected durable storage and verify archive coverage.
---

The workflow runs automatically (`workflow_run`) after every Run Benchmark, Recover Benchmark, Protected Labels Fan In, Score Terminal Release, and Prepare Jev Summaries run, scoped to that run's artifacts. Use `gh workflow run archive-github-artifacts.yaml --ref main` for a full inventory, or add `-f source_run_id=<run-id>` to re-archive one run. The job uses `legalforecastbench-official-eval-fan-in` and its existing S3 role. Preserve the protected-environment approval boundary; no local S3 writes, IAM widening, or provider calls are needed.

The workflow inventories every currently available artifact in this repository, including checkpoints from failed runs. Original ZIPs go to `s3://${LFB_RESULTS_BUCKET}/reports/github-artifacts/multi-ablation/<owner>/<repository>/artifacts/<artifact-id>.zip`. It never extracts artifact contents. A deterministic pointer at `by-run/<source-run-id>/<artifact-name>/<artifact-id>.json` names each ZIP and its GitHub SHA-256 digest; fan-in lists that prefix to restore an expired forecast package. An S3 denial prints the AWS error in the job log and fails the run. Names and source workflow identities remain in the snapshot and result indexes under `runs/`. This is preservation, not canonical benchmark publication.

The implementation entrypoint is `uv run python -m legalforecast.artifact_archive --help`. Normal operation is the protected workflow. Existing matching S3 objects are reused through the shared create-once helper; conflicting content fails. Per-artifact failures do not discard successful copies, but the run must report incomplete coverage and fail if any selected artifact could not be copied.

Inspect the final index and job conclusion before claiming completion. Report selected, archived, failed, and already-expired counts; a new artifact created after the snapshot is outside that invocation. Rerun through the same workflow to cover newer artifacts or remaining copies. Retain failed-copy evidence and never treat an expiring GitHub index alone as proof that the ZIPs reached S3.

Artifact downloads run before assuming the S3 role. The downloader checks GitHub API quota in bounded batches and waits for its reset when necessary; the upload phase then obtains fresh one-hour AWS credentials. Large inventories can therefore take one or more quota windows. Download failures remain failures even if successfully downloaded ZIPs are preserved.


Expired-input restoration uses `uv run python -m legalforecast.artifact_restore --help`. The shared reader selects an exact source run/name and optional artifact ID, verifies the archived pointer identity and ZIP digest, and rejects ambiguous pointers. Terminal scoring restores through its existing fan-in role. Benchmark recovery and Jev preparation use separate provider-free jobs under `legalforecastbench-official-eval-fan-in`, pass restored bytes through one-day current-run artifacts, then run their existing protected consumer jobs. Recovery reads the materialized cache without inheriting local AWS credentials. Missing archive bytes remain a blocker; this path cannot reconstruct artifacts that expired before preservation.

For an authorized complete historical forecast package whose original GitHub artifact no longer exists, use `preserve-retained-package.yaml` on `main`. Upload the complete ZIP to an **unpublished draft release** using routine brokered GitHub access; never commit the package or publish the draft. ZIP files belong at the root, with no wrapper directory. Name the asset `official-forecast-results-<original-run>-<attempt>.zip`. Dispatch with exact `asset_id`, lowercase hex `sha256`, `source_run_id`, and `source_attempt`. The workflow authenticates the asset API, checks it belongs to a draft, validates saved run identity and complete valid receipt/unit membership, then uses the existing protected fan-in OIDC role and immutable storage helper. Downloads precede storage credentials; validation runs again before upload.

These packages retain their distinct provenance at `retained-packages/<sha256>.zip` and `retained-by-run/<run>/<name>.json` beneath the normal archive prefix. A draft release asset ID is **not** a GitHub Actions artifact ID. The shared resolver accepts this source only for a named forecast package when ordinary archive pointers are absent; exact artifact-ID recovery never substitutes a retained package. Confirm workflow success and readback before claiming preservation.

GitHub requires push access to view unpublished draft releases ([REST release documentation](https://docs.github.com/en/rest/releases/releases#list-releases)). The first live import failed with `403 Resource not accessible by integration` under `contents: read`, before obtaining AWS credentials. The owner-authorized private draft transfer therefore grants `contents: write` only to the protected, main-only preservation job; the importer still performs authenticated GET requests only and never publishes or changes the draft. The workflow default remains read-only, checkout does not persist credentials, the explicit `GH_TOKEN` environment is set only for the download step (job actions can still access `github.token`), and the AWS role and digest/identity/readback checks remain unchanged. Do not replace a denied request with a fallback credential, new secret, public release, or broader IAM grant.

Local `legalforecast run resume` deliberately uses brokered GitHub access only. If the identity ZIPs have expired and local planning cannot reconstruct the run, dispatch the existing protected recovery workflow directly: `gh workflow run recover-benchmark.yaml --ref main -f source_run_id=RUN_ID -f source_run_attempt=ATTEMPT -f ref=main -f max_parallel=8 -f execute=false`. Inspect the protected plan first. When existing spend authority and the plan permit recovery, the same dispatch with `execute=true` requests settlement/reservation and child dispatch; it does not increase the approved ceiling. The fan-in restore job reads S3 and passes verified identity and state bytes to the official-eval recovery job. Do not supply local AWS credentials or write release storage locally.

For an authorized private experiment ZIP that is not a LegalForecastBench forecast package, use `preserve-retained-experiment.yaml` on `main`. Prepare the complete ZIP locally, name it `<experiment-slug>.zip`, and upload it only to an unpublished draft release. Dispatch with the exact asset ID, lowercase SHA256 and experiment slug. The protected fan-in job authenticates draft ownership, validates the intact ZIP, and uses the existing immutable archive helper and byte readback under OIDC. The ZIP is stored at `reports/retained-experiments/multi-ablation/<owner>/<repository>/<experiment-slug>/<sha256>.zip`; it is not admitted as a forecast restoration pointer or benchmark publication. Keep private task, answer and judge text out of commits. Verify storage readback before deleting the temporary draft asset and release. The module supports separate download and upload phases through `uv run python -m legalforecast.retained_experiment --help`; ordinary writes remain protected workflow operations.
