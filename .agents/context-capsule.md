## Purpose

LegalForecastBench is an academic, open-source benchmark that measures how well AI models forecast the outcome of a federal motion to dismiss from the written record the judge received, scored against a small fixed corpus of public federal court records (`.agents/AGENTS.md:3-5`). This repository is the *public* half of a two-repository split: it consumes immutable, outcome-blinded release inputs and retains evaluation, scoring, reporting, publication, and withdrawal; corpus acquisition, unitization, labeling, and provider purchasing belong to the companion private LegalForecastCorpus repository (`.agents/AGENTS.md:32-34`, `docs/architecture/public-private-release-boundary.md`). Its consumers are benchmark operators running protected GitHub Actions cycles, community contributors submitting multi-harness comparisons, and readers reproducing published arithmetic.

3. **INV-3 — Every write to official release storage goes through GitHub Actions under OIDC; local staging is closed.** The results and packet buckets and the artifacts KMS key carry resource policies naming only the OIDC roles, so an identity policy cannot re-open local writes (`.agents/AGENTS.md:44-52`). 5. **INV-5 — Two dependency pins are semantic, with recorded unlock conditions.** `pypdf==6.14.2` is pinned (not a floor) because its extracted text is hashed into `prompt_sha256`, so a bump retroactively invalidates settled disclosure attempts — #1022's 6.14.2→6.16.2 bump did exactly that; fenced by `tests/test_pdf_extractor_pin.py::test_pdf_text_extractor_stays_pinned_for_cycle_1_replay`. `[tool.ruff] target-version = "py313"` is deliberately one release behind `requires-python = ">=3.14"`, because py314 formatting adopts PEP 758 unparenthesized `except A, B:`, rewriting 34 files into source no pre-3.14 Python can parse (decision `LegalForecastBench-xf1t`). Both are non-obvious because a routine dependency or runtime bump reads as safe hygiene. Source: `pyproject.toml:25-36,70-80`.
6. **INV-6 — The supported full suite is parallel, and tests must be parallel-safe.** `uv run pytest -q -n 4 --dist=loadscope` is the supported command locally and in CI; new tests use per-test `tmp_path` for all files and SQLite databases, `monkeypatch` for env/cwd, ephemeral ports, no cross-test shared state, and never `os.fork()` — xdist workers are multi-threaded, so use a subprocess (`.agents/AGENTS.md:83-91`; `.github/workflows/ci.yaml:57-64`).
7. **INV-7 — Beads issues live in a Dolt SQL server; `.beads/issues.jsonl` is a passive export.** No `bd dolt push/pull` is needed and `bd import` is an anti-pattern during normal operation (`.agents/AGENTS.md:26-30,141`). Non-obvious because the JSONL file is visible in the tree and looks authoritative.
8. **INV-8 — Result class and contamination tier are two independent two-valued dimensions and must not be collapsed.** Result class compares a model's `release_timestamp` against the cycle's corpus anchor (pre-anchor / post-anchor); contamination tier compares its recorded training cutoff against the cohort's `eligibility_anchor`. Both arms are official and publishable, they are separately tracked/aggregated/ranked, and the headline stays the best pre-anchor row (`.agents/AGENTS.md:55-72`; owner directives `legalforecastbench-38gh`, `legalforecastbench-wjuo`). The older four-tier result classification is explicitly *not* adopted.
9. **INV-9 — Infisical paths for this repo are confined to `/agents/sandbox/legalforecastbench/` subdirectories**; sibling aliases outside that namespace must not be added or used (`.agents/AGENTS.md:40-42`).
10. **INV-10 — Process artifacts must justify themselves before they are built.** Any artifact only humans and status reports read — certificate, ledger, receipt, matrix, meta-report, readiness check, approval chain — must name its consumer, the capability it gates, the defect that actually happened, and when it gets deleted, or it is not built; this section supersedes older documents in the tree that still call for attestations, sealed deliverables, receipt cards, hashed approval scopes, or evidence tiers (`.agents/AGENTS.md:7-15`). ## Security surfaces & boundaries

This repository has real security surfaces and points at the fixed boundaries rather than restating them:

- **GitHub auth** — the secure-gate broker. Ordinary `git push` and `gh workflow run` work with routine short-lived tokens; secret and variable writes are human-approved server-side applies (`secure-gate-elevate set-variable --environment ...`) and the machine never receives a write token (`.agents/AGENTS.md:53`). See house rules §8 and the `secure-gate-elevate` skill.
- **AWS** — two accounts (artifacts vs org management), OIDC-only writes to official storage, resource policies naming only the OIDC roles, and a one-time human-admin bootstrap for role creation (`.agents/AGENTS.md:44-52`; `infra/official-eval-bootstrap/README.md`). Local staging is closed by design.
- **Secrets provider** — Infisical, confined to `/agents/sandbox/legalforecastbench/` subdirectories (`.agents/AGENTS.md:40-42`). House rules §8B govern which provider holds what; nothing in this repo overrides that.
- **Publication** — `legalforecast/publication/publication_guardrails.py` scans publication-bound text artifacts for named secrets, assignment-shaped secrets, bearer headers, AKIA keys, and provider account identifiers before anything is published.
- **Release** — PyPI trusted publishing is tag-only (`v*`), reruns the release check, and cannot be dispatched from an arbitrary branch (`README.md:101-103`; `docs/security/pypi-trusted-publishing.md`).
- **Public-repo hygiene** — INV-1/DR-1 above; this is a security property here, not a style preference.

This survey performed no privileged operation: no AWS call, no secret read, no provider call, no workflow dispatch, no `sudo`, and no change to any workflow, IAM, or policy file.
